How it's built
  • Microsoft Fabric · OneLake lakehouse
  • Data Factory pipelines
  • Mirroring / shortcuts
  • Dataverse link to Fabric

LMS and SIS exports land in one OneLake lakehouse on a schedule through Fabric Data Factory pipelines or Dataflows Gen2; databases that support it can be mirrored, and existing storage can be added as a shortcut. Outreach and advising records kept in Dataverse reach the same lakehouse through Dataverse's link to Microsoft Fabric.

Illustrative thresholds

How it's built
  • Fabric Activator rules
  • Scheduled Power Automate flow
  • Copilot Studio event triggers

Your team keeps scope, conditions and weights in a small rules table, so a threshold changes without anyone editing code. A Fabric Activator rule (for example, days since last login rises above 5, per student) or a scheduled Power Automate flow checks the lakehouse and starts the next step.

A Copilot Studio agent can also be woken by an event trigger, such as a Recurrence or a new Dataverse row. Event triggers need generative orchestration, count toward Copilot Credits, and run with the agent maker's credentials, so keep their scope narrow.

How it's built
  • Fabric notebook or SQL view
  • Lakehouse table per student

A scheduled Fabric notebook or SQL view adds up the weights of the active signals and writes one row per student: the total and each contribution behind it. Advisors can always see why a total is what it is.

If your institution also trains its own model in Fabric Data Science (tracked with MLflow, batch-scored with PREDICT), treat it as one more visible input. A model score is never the only reason to contact a student.

How it's built
  • Microsoft Teams connector
  • Office 365 Outlook / Azure Communication Email
  • Azure Communication Services SMS or Twilio
  • Dataverse contact history
  • Copilot Studio topics + SharePoint knowledge

Before sending, the flow reads the student's contact history in Dataverse: if someone already reached out within the spacing window, it waits and rechecks instead of sending a second message. Every message it does send is written back to the same table, so all offices see one history.

The message links to the Campus Copilot agent in Teams. Topics there answer "where do I get tutoring?" or "who handles my aid?" from your SharePoint support pages, and offer to book time with an advisor.

An informed conversation with a person · Fictional student

How it's built
  • Fabric data agent as connected agent
  • Microsoft Teams
  • Agent flow · create case
  • Dataverse, Dynamics 365 or ServiceNow

The Campus Copilot agent hands roster questions to a Fabric data agent over the retention lakehouse. With user authentication, each advisor sees only the students their data permissions allow.

When the student asks for help, or a band calls for escalation, an agent flow opens a case in Dataverse (or Dynamics 365 Customer Service, or ServiceNow through its Power Platform connector) with the signals, the contact history and the student's own words, so the advisor starts informed.

Connecting a Fabric data agent to Copilot Studio is in preview and validated in Microsoft Teams only, not Microsoft 365 Copilot.

Who decides
  • Rules set by your team
  • Escalations reviewed by people
  • Power Platform DLP policies
  • Microsoft Purview audit

The agent and flows notice and organise; people decide. Your team sets the signals, weights and bands. Escalation bands route to an advisor before any student is contacted, and the advisor chooses the intervention.

Student signals are education records. Keep access scoped with user authentication and data permissions, limit connectors with data policies in the Power Platform admin center, and audit agent activity with Microsoft Purview, all in line with your institution's records and privacy policies.
