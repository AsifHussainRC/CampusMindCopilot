02 THE ALUMNI AGENT

Ask once, on the alumni site. It goes to the right place.

ALUMNI WEBSITE · CHATNot signed in

Published to the website channel. Authentication uses "Authenticate manually" with a Generic OAuth 2 provider (the institution's alumni identity service) and "Require users to sign in" turned off, so anyone can ask about events or giving, and topics that touch a personal record ask the alum to sign in first. Every tool that changes something (register, sign up, update, set preferences) has "Ask the end user before running" set to Yes, which shows the confirmation in chat.

03 PREFERENCES FIRST

“No” is a setting every flow reads before it sends.

Ines Aldana ’09 · communication preferences

Outbound this week

    Preferences live in the CRM. The agents read them; they don't decide them.

    Fictional alum · Preference names vary by CRM and institution

    Preferences are fields on the CRM contact, such as Do not allow Email, Phone, Postal Mail and Bulk Email on the Dataverse contact table in Dynamics 365, or the matching fields in Salesforce or another advancement CRM, plus any solicitation codes the institution keeps. Each agent flow and cloud flow that sends (appeals, reminders, officer drafts) starts with a condition that reads them and drops anyone who has opted out. An opt-out made in chat runs a tool that writes the preference after the alum confirms. Retention and consent rules come from the institution's own policy; this page makes no legal claim.

    05 AGENT DRAFTS, OFFICER SENDS

    The agent writes the first draft. A person writes the last word.

    To: Tomasz Wieczorek Email allowed · checked in CRM

      Save this as a draft in Hollis’s mailbox? It will not be sent.

        Illustrative counts · not product output

        One donor: the agent drafts from the brief, the officer edits in chat, then a tool built on the Office 365 Outlook action "Draft an email message", running with end-user credentials and "Ask the end user before running" on, saves it to the officer's own Drafts folder. Nothing is sent by the agent. After an event: a cloud flow starts when attendance is final. It reads attendees from the events system (a connector such as Eventbrite, or a Dataverse table), drops opted-out contacts, sends the standard thank-you only after the events lead approves it with "Start and wait for an approval" (Approvals connector), and gives each portfolio prospect to their officer as a draft.

        Both agents use generative orchestration. Knowledge: the public alumni and giving pages (public website knowledge) and SharePoint for internal guidance. Tools: Power Platform connectors (Microsoft Dataverse, Salesforce, Blackbaud Raiser's Edge NXT, Office 365 Outlook, Approvals), custom connectors or MCP servers for other systems, and agent flows in Power Automate. The Dynamics 365 connector is deprecated, so Dynamics 365 data is reached through the Microsoft Dataverse connector. The Fabric data agent connection is preview and validated only in Teams. Admins set DLP policies and environments in the Power Platform admin center, and Microsoft Purview audits agent activity.
