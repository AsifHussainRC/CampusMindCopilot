FINANCIAL AID LAB

01 THE QUESTION

“Why is there a hold on my account?”

The answer usually lives in two or three systems owned by two or three offices. The student finds out by walking between them, often the week registration opens.

Money is one of the reasons students leave, and a missing form should never be the one that decides it. The Retention Lab shows the early-alert side of the same story.

The route is illustrative. The point: holds, balances and aid status sit in the student information system (SIS), the bursar or student-accounts system and the aid management system, each with its own office and front desk. One Copilot Studio agent, published to Teams and the student portal (website channel with Microsoft Entra ID sign-in), reads all three on the student's behalf and says which office owns the next step. It explains; it does not release holds or change aid.

Authentication is set to "Authenticate with Microsoft" (Entra ID), so the agent knows who is asking. The holds and balance tools pass the signed-in user's identity, never a student ID typed into chat, so a student can only reach their own record. There's no Power Platform connector for most SIS and bursar platforms. Not signed in, the agent answers only from public knowledge: the student-accounts pages in SharePoint or on the public site. Disclosure rules follow the institution's records policy (for US schools, its FERPA policy), set by the registrar, not by the agent.

03 MISSING DOCUMENTS

The aid is ready. One document is not.

Where Dani's aid stands

    Checklist for 2026–27

        Document names and stages are generic · Your institution's checklist differs · The agent files, staff decide

        File uploads are on in the agent's settings (Teams and website channels accept PDF, JPG and PNG, up to 15 MB a file). A topic picks the file up from System.Activity.Attachments and passes contentBytes and name to an agent flow (Power Automate). The flow saves it to a SharePoint document library with the student, aid year and document type as metadata, and adds a "ready for review" row in Dataverse that the aid office works from. The agent never marks a document accepted, never decides on verification, and never changes a package. Those stay with aid staff in the aid system. Whether an application is selected for verification, and what's needed, comes from the aid system and the institution's rules.

        Payment plan: the enrol tool calls the bursar or payment-plan provider's API (custom connector or MCP tool) and has "Ask the end user before running" set to Yes, so the student sees the terms and confirms before anything is written. Refund: a read-only tool returns refund status and the method on file; the agent explains the institution's timing from knowledge and doesn't promise a date. Tax form: the US annual tuition statement (Form 1098-T) is answered from the institution's FAQ in SharePoint knowledge, with citations, plus a link to download it from the student portal. The agent explains what the form is and where to get it. It doesn't give tax advice and suggests a tax professional for anything about the student's own return.

        Fictional student and counselor · Timing and channels are set by the aid office

        Reminders: a scheduled cloud flow (Recurrence trigger) queries the aid system for students with open checklist items and a deadline inside the window, then sends each one a proactive message in Teams through the Microsoft Teams connector ("Post message in a chat or channel", posted as the Copilot Studio agent) and an Outlook email. Proactive Teams messages only reach students who have the agent installed in Teams, so keep email as the fallback. Handoff: the Escalate system topic with a Transfer conversation node passes the whole conversation and variables to a live engagement hub such as Omnichannel for Customer Service, or, without one, the topic books a counselor appointment and posts the summary to the aid team in Teams. The counselor, not the agent, talks about options like emergency funds or a professional-judgment review.

        07 HOW IT'S BUILT

        One agent explains. Staff decide.

        Who does what

        Nothing that changes money, eligibility or a record happens without a person saying yes.

        Every tool that writes, such as enrolling a payment plan or filing a document, has "Ask the end user before running" on, or runs inside an agent flow that ends in a staff step (a Dataverse review queue or the Approvals connector's "Start and wait for an approval"). Admins limit who can use each agent with Entra ID groups, set environments and data loss prevention (DLP) policies in the Power Platform admin center, read sessions and outcomes in Copilot Studio analytics, and audit agent activity in Microsoft Purview. Agents with event triggers run those triggers with the maker's credentials, so the reminder flow uses a dedicated service account with read-only access to the aid data it needs.
