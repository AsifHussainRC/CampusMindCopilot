02 ASK THE GUIDELINES

Answers from the sponsor's own document, with the page it came from.

Dr. Tomasz Wren is applying to the (fictional) Northfield Foundation Early Career Award. Pick a question.

TEAMS · 1:1 WITH CAMPUS COPILOTKnowledge: Sponsor guidelines library

Every answer cites the guideline the office uploaded. When the guide is silent, it says so.

The pre-award office keeps a SharePoint document library of sponsor guidelines and solicitations (PDFs), added to the agent as a SharePoint knowledge source. Answers come with citations to the file. SharePoint knowledge respects the signed-in user's permissions, so draft or internal-only guidance stays with staff. Agent instructions say: answer only from the uploaded guidelines, quote the section, and if the guideline is silent or ambiguous, say so and offer a hand-off to a pre-award officer. Sponsors here are fictional; real sponsor rules change often, so the office owns keeping the library current.

    Flags are questions for the PI and the pre-award officer, not edits to the proposal.

    A prompt tool (Tools → New tool → Prompt) with two document inputs: the draft PDF the PI uploads in chat, and the solicitation. Prompt document inputs accept PDF, PNG and JPG. The prompt's instructions ask it to list the solicitation's required sections, page limits and budget-justification items, mark each as present, missing or inconsistent, and quote where it looked. It is told never to rewrite or suggest research content. The output is a checklist for people to review. The pre-award officer still does the formal review in section 05.

    04 COMPLIANCE HAND-OFFS

    It asks the screening questions. The compliance offices decide.

    Answer the way Dr. Wren would. The agent never says "you don't need review."

    A Copilot Studio topic asks a fixed set of screening questions with question nodes (multiple-choice: Yes / No / Not sure). The wording comes from the institution's own compliance offices. Any Yes or Not sure triggers a hand-off message, never a determination. The PI confirms, then an agent flow (Power Automate) posts the proposal details to that office's Teams channel with the Microsoft Teams connector, or emails the office with Office 365 Outlook. The agent's instructions forbid legal or compliance conclusions; it points to the institution's policies and the office that decides.

    05 ROUTING & REMINDERS

    Chair, dean, sponsored programs. In order, in Teams, with a record.

      Deadline reminders · tap a day

      Routing is an agent flow started from the agent once the PI confirms. It uses the Standard approvals connector's "Start and wait for an approval" action three times in sequence: department chair, then dean, then the sponsored programs officer. Each step only starts after the previous one approves; a rejection stops the flow and returns comments to the PI. Approvers respond from a Teams adaptive card, an Outlook email or the Approvals app in Teams. Multistage approvals in agent flows are also available but are in preview. Reminders are a separate scheduled cloud flow (Recurrence trigger, daily) that reads open proposals from a Dataverse table and posts reminders in Teams. Every flow action consumes Copilot Credits when it runs as an agent flow.

      06 AFTER THE AWARD

      "How much is left?" answered from the ledger. Only for your own awards.

      TEAMS · FABRIC DATA AGENT · GRANTS LEDGERDr. Wren

      Coming due on your awards

        Fictional awards and amounts · Illustrative figures · not product output

        Spend questions go to a Fabric data agent added to the Copilot Studio agent as a connected agent (preview). It is validated only in Microsoft Teams and isn't supported in Microsoft 365 Copilot, so this agent is published to Teams. The data agent queries a grants ledger in a Fabric lakehouse or warehouse, kept up to date from the institution's financial system. It is set to user authentication, so each question runs with the PI's own permissions; the data team enforces "PIs see only their awards" with row-level security on the ledger. Responses from a Fabric data agent may leave Fabric's compliance boundary, which the data owner should review. Questions about whether a cost is allowable go to the post-award officer: the agent reports numbers, it doesn't rule on allowability.

        07 HOW IT'S BUILT

        One agent in Teams. Officers keep the decisions.

        Who decides

        After one cycle · illustrative

        Stack, top to bottom. Copilot Studio agent with generative orchestration and instructions that bar scientific writing and compliance determinations. Knowledge: SharePoint library of sponsor guidelines. Tools: a prompt (readiness check), agent flows using the Standard approvals, Microsoft Teams, Office 365 Outlook and SharePoint connectors. Connected agent: Fabric data agent over the grants ledger (preview, Teams only, user authentication). Topics: compliance screening and hand-off to a person. Data: Dataverse table of proposals in flight. Governance: Entra ID groups for who can use it, Power Platform admin center environments and DLP policies, Copilot Studio analytics, Microsoft Purview audit, Copilot Credits consumption reporting. Records are kept under the institution's own retention policy.
