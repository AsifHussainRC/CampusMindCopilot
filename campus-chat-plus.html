CAMPUS CHAT PLUS LAB

01 ONE CAMPUS

Every office bought its own AI.

Before: five offices, five contracts, five logins, and nobody can see what went where. After: each office builds its agents in Copilot Studio inside the institution's own Microsoft tenant. Everyone signs in with their Entra ID account, admins set environments and data loss prevention (DLP) policies in the Power Platform admin center, and agent activity lands in the Microsoft Purview audit log.

02 ONE BOX

Every agent, one place.

@ an agent. Each agent brings its own model.

This is the chat box in Microsoft 365 Copilot Chat or Teams. People @mention any agent they've added, and each agent shows its conversation starters. People don't pick a model per message: each agent's maker picks its primary model on the agent's Overview page in Copilot Studio. GPT Chat Latest is the default. Claude Sonnet 4.6 and Claude Opus 4.8 are generally available once an admin turns on external models. Mistral (preview) and Grok 4.2 (experimental, US early access) aren't meant for production. Prompt tools can call Azure AI Foundry models such as Llama or DeepSeek.

03 AGENT STORE

Build an agent once. Anyone adds it.

An office publishes its agent to the Teams and Microsoft 365 Copilot channel, then submits it for admin approval. Once approved it appears in the Built by your org section of the Microsoft 365 Agent Store (and Built for your org in the Teams app store), and only an admin can remove it. For a smaller pilot, "Show to my teammates and shared users" lists it under Shared with you instead. Nobody installs software; people add the agent and it shows up under @.

04 CONFERENCE GUIDE

Ask the conference. Get the day.

One Copilot Studio agent, four kinds of source: an MCP server tool for the live session schedule, SharePoint knowledge for speaker bios (read with the user's own permissions), an agent flow in Power Automate that looks up rooms, and public website knowledge that searches the conference site through Grounding with Bing Search. The chips show which sources answered. Sessions and names are illustrative.

05 GROUP CHAT

Bring people in. Bring the agent.

The maker turns on "Use this agent for group and meeting chats" in the Teams channel settings. Colleagues add the agent to a Teams group chat and @mention it; messages without an @mention aren't sent to it. The calendar invite is built with an agent flow that uses the Office 365 Outlook connector. In group chats and channels, Copilot Studio agents can't use knowledge that needs end-user sign-in, such as SharePoint, so this agent answers here from its public website knowledge and MCP schedule tool.

06 AGENTS CALLING AGENTS

One question. Three agents.

Campus Copilot uses generative orchestration to split the question and pick agents by their descriptions. Conference Guide is a connected agent: a separate Copilot Studio agent that its office publishes and maintains. Schedule helper is a child agent that lives inside Campus Copilot and calls Outlook through a connector. Campus Facilities is a Fabric data agent over the facilities lakehouse, connected in preview; Microsoft validates that pairing only in Teams, and with user authentication each person sees only data they're allowed to see.

07 ON YOUR WEBSITE

Same agent, on your website.

Publish to the Custom website channel and paste the iframe snippet (or use Web Chat with a token endpoint). With No authentication, anyone with the link can chat, and the agent can only reach public information such as its public website knowledge. For a staff page, choose Authenticate manually with Microsoft Entra ID so people sign in and SharePoint knowledge works. Separately, "Require secured access" makes clients present a Direct Line secret or token; on its own that doesn't sign anyone in.

08 BUILD IT

Build it. Then ask it.

There's no shared demo to open. Each campus builds this in its own tenant, in about an afternoon for a first version.

Tick the steps as you build in Copilot Studio, then paste the questions into the Test pane before you publish. Name a date, not "day two", so the agent doesn't count preconference days. Connected Fabric data agents are in preview; check your tenant's admin settings for external models and the Agent Store approval flow first.
