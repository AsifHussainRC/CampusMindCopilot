01 THE RUNAWAY BILL

One pool of credits. No idea who spent it.

Open the Power Platform admin center

 

Copilot Studio bills in Copilot Credits from a prepaid pack pooled across the tenant, or pay-as-you-go through an Azure subscription. Reasoning models add a premium charge of 10 credits per 1,000 billed tokens on top of the feature rate, so a few long turns can cost a lot. If an environment draws on the tenant pool and the tenant reaches 125% of its prepaid capacity, Microsoft blocks the agents in those environments, even mid-conversation. The tenant admin gets an email and a notice in the Power Platform admin center.

02 WHERE THE CAP SITS

Four places to stop the spend.

TENANT · PREPAID POOL
ENVIRONMENT · ALLOCATION
AGENT · MONTHLY LIMIT
PAY-AS-YOU-GO BILLING PLANAzure subscription · one or more environments

All four levers are in the Power Platform admin center under Licensing > Copilot Studio. Manage capacity sets each environment's allocation and its overage source. A billing plan links environments to an Azure subscription. Manage agents sets a monthly limit for each agent, with notifications and an optional hard stop. There's no per-user credit cap. You control people through sharing, security groups and the Copilot Author setting. The user consumption report tells you who used what.

03 ENFORCEMENT MODE

What happens when it runs out.

When this environment's allocation runs out

Overage sources are set per environment under Capacity overages. You can draw from unallocated tenant capacity (the default for environments with no allocation set), bill a pay-as-you-go plan, or neither. An environment with credits left in its own allocation isn't blocked, even if the tenant is past 125%. An agent that hits a monthly limit with hard stop is turned off whatever the overage setting. Limits take effect after a delay, not instantly. Agent flows are checked separately: new runs are blocked only when the environment has no credits left. Power Automate cloud flows use Power Automate licensing, not credits.

04 THE PUBLIC AGENT

Anyone on the internet can use it.

A monthly agent limit is charged to that agent, so abuse uses up one budget and not the shared pool. Limits take effect after a short delay, so a few more requests get through first. Two more controls: Web channel security (Require secured access) makes clients present a Direct Line secret or token. A data policy that blocks the "Chat without Microsoft Entra ID authentication in Copilot Studio" connector stops anyone publishing an agent without sign-in. Anonymous usage appears in the user report under user ID 00000000-0000-0000-0000-000000000000.

05 WHO SPENT WHAT

The invoice, itemised.

Beyond the bill: where the signals live

Under Licensing > Copilot Studio you can download consumption reports by environment, by agent, or by user (user rows for standard-harness agents). The detailed report adds Product / AI feature, Channel, LLM model and Knowledge sources / Tool used. It doesn't show token counts or single conversations. Quality data comes from each agent's Monitor page in Copilot Studio. Your own telemetry goes to Application Insights, and audit records go to Microsoft Purview. Agent inventory is in the Microsoft 365 admin center (Agents > All agents > Registry).

06 ROLES & PERMISSIONS

Same platform. Different powers.

Permissions come from several places. The Power Platform Administrator is an Entra ID role. Environment Maker, System Administrator and Bot Transcript Viewer are Dataverse security roles in each environment. Editor, Viewer and Analytics Viewer are sharing roles on each agent. You can also limit who can build agents with the Copilot Author setting (a security group). Managed environments add sharing limits, such as no Editor sharing or a cap on the number of viewers. Environment group rules lock those settings across every member environment.
