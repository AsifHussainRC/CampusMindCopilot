Advising

The meeting is thirty minutes. Finding out who the student is takes most of it.

  • Copilot Studio agent
  • Advisors only · in Microsoft Teams
  • The advisor decides

One Copilot Studio agent, published to the Microsoft Teams channel and shared only with the advising security group in Entra ID. Advisors use it in a 1:1 chat. Students never talk to this agent. It reads the student record and drafts work for the advisor, and nothing goes to a student until the advisor confirms it.

02

Before one meeting

Eight places hold the answer. None of them hold all of it.

Eight open tabs The advisor assembles it Every meeting, from scratch

Representative source systems · How each one connects is shown when joined · Names vary by institution

A Recurrence event trigger wakes the agent early each morning. It reads the day's advising bookings from the advisor's Outlook calendar and calls its tools for each student. Student information and the degree audit come through an MCP server. The LMS, financial aid and career systems come through Power Platform connectors or custom connectors. Tutoring visits and earlier notes come from Dataverse. Campus life comes from SharePoint knowledge. The brief is posted to the advisor in Teams. One caveat: event triggers run with the agent maker's credentials, so use a dedicated service account with read-only access to advising data. Generative orchestration must be on, and every trigger run uses Copilot Credits.

The brief

Sorted by what needs saying, not by which system said it.

Fictional student · Every line names the tool or source it came from

The agent writes the brief from what its tools return. Its instructions tell it to sort lines into three groups and to name the tool or source behind each line. Answers from knowledge sources such as SharePoint come with citations. The advisor can ask follow-up questions in the same Teams chat. Questions about the whole caseload, such as "which of my advisees have a hold?", go to a connected Fabric data agent (preview, validated only in Teams). Set it to user authentication so each advisor sees only the students they're allowed to see.

04

The check

“Can I drop this course?” is five questions in four systems.

Advisor asks in Teams Can Maya drop ECO-415?

      Illustrative consequences · Rules are set by the institution · The agent reads, it does not drop

      With generative orchestration, the agent plans one question as several tool calls in a single turn. Here it calls a registration tool and a degree audit tool on the SIS MCP server, a custom connector for financial aid, and SharePoint knowledge for the academic calendar. It then puts the answers together, with each line labelled by its source. All of these tools only read data. If you later add a tool that changes a registration, set "Ask the end user before running" on that tool so the advisor has to confirm each run.

      05

      After the meeting

      What was promised survives the walk back to the office.

        Open promises 9 carried across the caseload, each with a name and a date

        The advisor writes and approves the note. The record keeps the commitment.

        The advisor pastes rough notes into the Teams chat. For a transcribed Teams meeting, an agent flow can fetch the transcript from Microsoft Graph instead, through a custom connector with OnlineMeetingTranscript.Read.All. This only works if the Teams admin allows Graph access to transcripts. The agent drafts a note with a summary, decisions and actions, and the advisor edits it. Agent flows (Power Automate) then save the note and each promise as Dataverse rows, or in the CRM through its connector, email the student a summary through Outlook, and add the follow-up to the calendar. Each of these tools has "Ask the end user before running" turned on, so the advisor sees and confirms every send.

        Meeting notes and promises are stored in Dataverse, and Link to Microsoft Fabric copies them into OneLake next to the SIS data. A Power BI report shows the charts. Deans can ask their own questions in Teams through the Fabric data agent. Admins control who can use the agent through Entra ID groups, and set environments and data loss prevention (DLP) policies in the Power Platform admin center. Copilot Studio analytics shows sessions, outcomes and advisor feedback. Microsoft Purview audits agent activity, and Copilot Credits consumption is reported per environment.
