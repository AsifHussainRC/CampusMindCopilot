Student services

Students shouldn't need an org chart to get an answer.

  • One Copilot Studio agent
  • Teams and the website
  • Seven offices behind it
  • Staff decide

One main Copilot Studio agent ("Campus Copilot") is the front door. It uses generative orchestration to pass each question to a specialist agent for the office that owns the answer. It's published to Microsoft Teams for signed-in students and to the university website through Web Chat. Specialists answer from their own knowledge and tools. Anything that changes a record, money or eligibility goes to a person.

    02

    How it routes

    One agent at the door. A specialist behind it for every office.

    Ask the front door

    Child agent = lives inside the main agent · Connected agent = its own published agent, owned by the office

    Multi-agent orchestration in Copilot Studio. Child agents sit inside the main agent and group instructions, tools and knowledge. Connected agents are separate Copilot Studio agents in the same environment. They must be published, and each office can manage and publish its own. The main agent's orchestrator picks agents by their name and description, and one question can call more than one. Microsoft suggests splitting into connected agents once a single agent has more than about 30 to 40 tools, topics and agents to choose from. Each extra hop adds some latency. An agent that has connected agents of its own can't also be a connected agent for another main agent.

    03

    Public or personal

    Anyone gets the rules. Only the student gets their own record.

    What the agent can see

      Fictional student · Illustrative answer · Records shown only to the signed-in student

      Set the agent's authentication to Authenticate manually with Microsoft Entra ID and clear "Require users to sign in". Public questions are then answered without sign-in, from website and SharePoint knowledge. Topics that need a personal record start with an Authenticate node, so the student signs in only when they ask about their own account. Tools then call the SIS and the bursar system with the student's identity, so they see only their own data. In Teams, configure single sign-on (SSO) with Entra ID so students aren't prompted again. If you'd rather keep a public agent completely separate, publish a second agent with No authentication on the website. Follow the institution's records policy on what may be shown in chat.

      04

      After hours

      Offices close at five. The questions keep coming.

      Same question, different hour

      Illustrative figures · not product output

      The agent answers from knowledge and read-only tools at any hour. The after-hours path is a pattern you build, not a switch you turn on. The Escalate topic checks the office's hours, either with a condition or an agent flow that reads hours from a Dataverse table. When the office is open, it transfers the conversation live. When it's closed, it calls an agent flow that creates a case and tells the student when to expect a reply. Each office owns its hours and its queue.

      Live: the Escalate system topic ends in a Transfer conversation node. Its "Private message to agent" carries a summary the agent writes, and Dynamics 365 Customer Service receives the full conversation history and the variables collected. It routes the chat to the international office queue. Other engagement hubs, such as ServiceNow, connect through the generic handoff pattern, which needs integration work. Closed: an agent flow creates the case instead. That's the ServiceNow connector's Create Record action (Premium), or a Case row in Dynamics 365 Customer Service through the Microsoft Dataverse connector's Add a new row. The older Dynamics 365 connector is deprecated. Advice on immigration status comes only from the designated school official.

      06

      How it's built

      Microsoft parts, put together for one front door.

        Who decides

        The agent reads, explains and prepares. Staff change things.

        Connector names checked against the Power Platform connector reference · Systems vary by institution

        Tools that only read run when the orchestrator calls them. Tools that write, such as creating a case, are set to "Ask the end user before running", so the student confirms what will be sent. Changes to holds, charges, aid or enrollment aren't tools on this agent at all. They go to staff as a case or a live transfer. Admins limit who can use each agent through Entra ID and sharing. They set environments and data loss prevention (DLP) policies in the Power Platform admin center. Microsoft Purview audits agent activity.
