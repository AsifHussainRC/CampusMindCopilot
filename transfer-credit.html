The figures are illustrative. The point: most incoming courses already have an approved rule in the institution's equivalency table, yet every transcript still waits in one queue. File uploads are turned on in Settings → Generative AI → File processing capabilities (supported on Teams and the website / Direct Line channels, not on the SharePoint channel; PDF up to 15 MB and 40 pages). A topic picks up the file with a Question node set to identify a File, or with First(System.Activity.Attachments), and passes contentBytes and name to an agent flow. In the flow, AI Builder's Process documents action runs a custom document processing model trained on the transcript layouts you receive and returns each field with a confidence score. For layouts you haven't trained on, a Run a prompt node with a document input and JSON output can do the same job. Azure AI Document Intelligence (form recognizer) is the pro-code alternative. Note that a prompt added directly as an agent tool can't take a document input yet, which is why the extraction runs inside the flow. Low-confidence rows are shown back to the student to confirm.

03 MATCH TO THE TABLE

Rules the registrar already approved, applied in seconds.

      Match confidence is a score the flow computes from the rules below · Illustrative

      The equivalency table is a Dataverse table (sending institution, course, home course, credits, minimum grade, status, approved by, effective term). The flow looks up each course with the Microsoft Dataverse connector's List rows action. An approved row is an "Approved rule". When there's no row, a Run a prompt node compares the extracted course title and the sending college's catalog description with your own catalog and proposes a "Likely" equivalent; the flow scores it and never marks it approved. Courses with no plausible equivalent go to "Needs evaluator review". Grade and pass/fail policy (here: C- or better) is a plain condition in the flow. The confidence labels are your own scoring, not a Microsoft feature.

      04 UNOFFICIAL PROGRESS

      Same courses, different major, different answer.

      Unofficial estimate Not a credit evaluation. Your official evaluation comes from the Registrar after admission.

      Fictional programs and requirements · Uses the transcript picked in section 02

      Switching program calls a tool that runs a what-if check. If your degree audit system exposes one, wrap it in an MCP server and add it as a tool (MCP tools are GA in Copilot Studio). Otherwise, an agent flow sums the mapped courses against a Dataverse table of program requirements. The agent's instructions require the "Unofficial estimate" label on every answer, and the transfer policy page in SharePoint is a knowledge source, so policy answers come with citations. Only approved rules and likely matches count, and pending courses are shown separately so the student isn't told something the Registrar hasn't decided.

        Each "Likely" or "Needs review" course becomes a row in a Dataverse evaluation request table. Evaluators work the queue in a model-driven app or in Teams. A cloud flow can also send an approval with the Standard approvals connector ("Start and wait for an approval"); multistage approvals in agent flows are preview. Because a synchronous agent flow must answer the agent within about two minutes, the wait happens in a separate flow that starts from the Dataverse "When a row is added, modified or deleted" trigger, not inside the chat. Only after the evaluator decides does the flow write the equivalency row. That's the learning loop: a lookup table getting better, not a model retraining itself. The evaluator agent in Teams has a connected Fabric data agent (preview, validated only in Teams) over the same tables, linked into OneLake with Link to Microsoft Fabric.
