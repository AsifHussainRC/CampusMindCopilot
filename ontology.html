01 ARCHITECTURE

A question goes all the way down.
Only the answer comes back.

 

Campus Copilot is a Copilot Studio agent published to Microsoft Teams. Each Fabric data agent is added to it as a connected agent (preview), and the orchestrator calls one when the question matches the data agent's description. A data agent can use up to five sources, including lakehouses, warehouses, Power BI semantic models, KQL databases and Fabric IQ ontologies. Its connections are read-only. Fabric IQ includes the ontology item (preview) and Power BI semantic models, both built over OneLake. Data arrives in OneLake through mirroring, shortcuts, pipelines and Dataflows Gen2, and the source systems keep running unchanged.

The first use case is cheaper without a layer. By the tenth, it isn't. Point to point means every agent, flow and report keeps its own connector, credentials and copy of the logic. With Fabric, each system lands in OneLake once. Data agents, Power BI reports, notebooks and Copilot Studio then read the same governed tables and reuse the same semantic model measures.

03 THE SYSTEMS

Thirteen systems that never talk.

ONELAKE · ONE GOVERNED COPY

Thirteen contracts · thirteen logins · thirteen definitions of a student

Each system comes in a different way. Mirroring replicates a supported database into OneLake in near real time. That list includes Oracle, so a Banner database can be mirrored, along with SQL Server, Snowflake and SharePoint lists (preview). Shortcuts point at data where it already sits, without copying it. Data Factory pipelines, Copy jobs and Dataflows Gen2 cover the rest using built-in connectors such as Salesforce objects, Dataverse and ServiceNow. Workday, Canvas and Slate have no dedicated Fabric connector, so they're pulled with the generic REST connector or from scheduled file (SFTP) exports. That's a pattern you build.

04 WHO SEES WHAT

Same question. Same layer. Different rows.

Entra IDOneLake security · rows & columnsSemantic model RLSPurviewAuditRead only

A prompt isn't a security boundary. In Copilot Studio, set the connected Fabric data agent to User authentication, not Agent author authentication, so every query runs with the asker's own Entra ID credentials. Rows and columns are then limited by OneLake security roles or row-level security on the semantic model. Each person needs at least read access to the data agent and to its underlying sources. The data agent stays read-only and follows Purview policies on its sources. Its activity can be audited in Purview.

06 WORK IQ

The decision is not in the database.

 

The record knows a student is blocked. Only the mailbox knows whether anyone did anything about it.

Work IQ is Microsoft 365's workplace intelligence layer. Alongside Fabric IQ, it's part of Microsoft IQ. It reasons over the asker's own email, meetings, Teams chats, OneDrive and SharePoint files and people context. Results are permission-trimmed, so a staff member only sees threads they already have access to. In Copilot Studio, Work IQ is generally available for agents on the GitHub Copilot harness, and Work IQ tools are in preview for other agents. Usage is billed in Copilot Credits, and a tenant admin has to enable Work IQ first. Here, Fabric supplies the 25 blocked students and Work IQ supplies the email threads. Five were named in an email between two administrators. None of the 25 got a message. A conversation nobody answers never becomes a case, so the record shows nothing.
